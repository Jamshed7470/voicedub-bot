# Аудит кода перед VoiceDub Studio v2 (Фаза 0)

Дата: 29.08.2026. Базовая ревизия: `75b18ca`.

Документ отвечает на три вопроса: что уже есть, что из этого ломает
инвариант «один человек = один голос», и как имена из спецификации
ложатся на реальные модули проекта.

---

## 1. Соответствие имён: спецификация → реальный код

Спецификация написана в терминах `voicedub/<пакет>/`. Корень проекта и есть
папка `voicedub/`, поэтому пути отображаются напрямую: `voicedub/identity/` →
`identity/` рядом с существующими `core/` и `bot/`.

| Путь в спецификации | Реальный путь | Статус |
|---|---|---|
| `voicedub/core/*` | `core/*` | существует |
| `voicedub/bot/*` | `bot/*` | существует |
| `voicedub/identity/` | `identity/` | создаётся в Фазе 1 |
| `voicedub/voices/profiles.py` | `voices/profiles.py` | создаётся в Фазе 1 |
| `voicedub/voices/{bank,casting}.py` | `voices/{bank,casting}.py` | Фаза 4; частично заменяет `core/voicebank.py` |
| `voicedub/synth/*` | `synth/*` | Фаза 1 |
| `voicedub/project/*` | `project/*` | Фаза 2 |
| `voicedub/studio/*` | `studio/*` | Фаза 2–3 |
| `data/jobs/<job_id>/` | то же | существует |

## 3. Кодовые пути, подлежащие удалению

Найдены поиском `get_conditioning_latents|choose_style_ref|speaker_wav`.

| Файл:строка | Что там | Приговор |
|---|---|---|
| `core/tts.py:40-76` | `choose_style_ref()` — выбирает референс **на каждый сегмент**: вырезка оригинала этого же сегмента ≥ 3 с, иначе референс по эмоции, иначе `ref_main` | **удалить** — это ПРИЧИНА 1 |
| `core/tts.py:149-167` | `_conditioning()` — `get_conditioning_latents` внутри синтеза, LRU-кэш на 32 записи по пути к файлу | **удалить** — латенты считаются один раз в `voices/profiles.py` |
| `core/pipeline.py:443-447` | развилка `bank_mode` / `choose_style_ref` в цикле синтеза | **заменить** загрузкой заблокированного профиля |
| `core/speakers.py:127-140` | сборка `refs_emotion` — банк эмоциональных референсов на спикера | **удалить**: разные референсы = разный тембр |
| `core/tts.py:198-235` | `synthesize(speaker_wav=…, preset=…)` — публичный API вокруг пути к wav | **заменить** на `TTSEngine.synthesize(text, lang, profile, speed, seed)` |

Почему кэш латентов не спасал: ключ кэша — **путь к файлу референса**, а
`choose_style_ref` для каждого сегмента ≥ 3 с создавала *новый* файл
`style_<id>.wav`. Кэш попадал только на короткие реплики. То есть чем
длиннее и выразительнее реплика, тем вероятнее у неё был свой уникальный
тембр — ровно то, на что жалуется пользователь.

## 4. Baseline: замер до изменений

Данные из реальных задач в `data/jobs/` (турецкие фильмы, дубляж на русский).

| Задача | Длительность | Сегментов | **Спикеров найдено** | Референс < 8 с |
|---|---|---|---|---|
| `7029743a3005` | ~117 мин | 1522 | **58** | 9 |
| `882130650cb2` | ~117 мин | 1565 | **58** | — |
| `879a4de87ad4` | ~103 мин | 1248 | **39** | 6 |

В художественном фильме говорящих ролей обычно 10–20. Найдено 39–58 —
прямое подтверждение ПРИЧИНЫ 2: pyannote дробит одного человека на
несколько кластеров, и каждый кластер получает собственный профиль голоса.

Дополнительно из логов последнего прогона: 58 спикеров при 52 доступных
русских голосах в банке — голоса начали выдаваться повторно и не тому полу,
о чём в логе есть предупреждение.

Попарная схожесть синтезированных сегментов одного спикера **до изменений
не измерялась** — метрики не существовало. Она вводится в Фазе 1
(`synth/qc.py`) и становится критерием приёмки (≥ 0.75).

## 5. Инварианты и где они проверяются

| Инвариант | Место проверки |
|---|---|
| INV-1 один speaker_id ↔ один профиль | `synth/render.py` (assert), отчёт `qc.identity_report` |
| INV-2 нет синтеза без профиля | `synth/engine_base.py` (assert), тест-grep `test_no_per_segment_reference` |
| INV-3 правки пользователя переживают рендер | `project/store.py` + `identity/registry.py` |
| INV-4 в UI видно спикера, голос, уверенность, QC | `studio/` + поля `Segment` |
| INV-5 рендер заблокирован на REVIEW | `pipeline.py` review gate, API `/approve` |
| INV-6 старый сценарий при `STUDIO_ENABLED=false` | `core/config.py:studio_enabled`, тест `test_legacy_flow_with_studio_disabled` |

Важно: фиксированные профили и Identity QC работают **всегда**, независимо
от `STUDIO_ENABLED`. Флаг выключает только точку проверки человеком
(review gate и веб-интерфейс) — иначе баг с плавающим голосом остался бы
у всех, кто студию не включил.

## 6. Риски, замеченные при аудите

1. **Кэш анализа.** `core/cache.py` кладёт `speakers.json` и `transcript.json`
   в `data/cache/<key>/analysis_<hint>/`. После смены алгоритма спикеров
   старый кэш отдаст старые 58 кластеров и исправление «не применится».
   Кэш анализа нужно версионировать — см. `DECISIONS.md`, решение D-07.
2. **Диск.** 96 % занято. Профили (`voice_profile.pt` ≈ 1–2 МБ на спикера)
   и превью-синтез добавляют немного, но `project_retention_days = 7`
   означает, что задачи перестают удаляться сразу после отправки.
   Уменьшено хранение медиа — см. D-08.
3. **58 спикеров × ECAPA-эмбеддинги на 1500 сегментов** — это ~1500 прогонов
   модели на файл. Батчирование обязательно, иначе стадия займёт минуты.
